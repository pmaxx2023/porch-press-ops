# PP-ELEANOR-AU-001 — Blind Play and Agent-Compatibility Protocol

This protocol does not contain the solution. It defines what must be observed before product, duration, difficulty, compatibility, and release claims are approved.

## Test layers

Do not combine these into one pass/fail label.

| Layer | Tester | Question answered |
| --- | --- | --- |
| Structural | Validator and implementation tests | Are IDs, routes, dependencies, scenes, state, and answer contracts internally valid? |
| Retrieval | Clean external-agent sessions | Can ordinary prompts locate/open/cite the controlled sources without privileged slugs? |
| Logic | Blind human solver | Do visible records uniquely support the reconstruction? |
| Interaction | Human on desktop/mobile/accessibility paths | Can the player operate the portal, archives, claim board, save, and finale? |
| Drama | Blind human viewer/player | Do reveals land, conflicts feel earned, and cast remain distinct without overwhelming the investigation? |
| Commercial | Clean customer-path tester | Does the purchased package start and complete exactly as promised? |

An agent reaching the answer does not prove human playability or fun. A human enjoying a reveal does not prove the evidence supports it.

## Required preconditions

- Candidate build has a unique version/commit and protected preview state.
- All intended archive pages and recovery routes are present for the tested tier.
- Validator passes for the exact data packets.
- Owner_Bot supplies a spoiler/forbidden-term scan list privately.
- Test accounts, owner traffic, bots, and production analytics are separable.
- Testers have not seen the private package, GitHub planning issue, solution, prior test recordings, or a completed player's prompts.

## Minimum release sample

1. **Three blind human solo players** unfamiliar with the answer.
2. **Two full player-agent configurations** using different available web-capable agents.
3. **One no-index route** in which search discovery is assumed unavailable and the player must use citations plus hints.
4. **One mobile-first run** at a phone viewport.
5. **One keyboard and screen-reader-focused pass** for every required action and clue.
6. **One clean customer simulation** from delivery/start guide through completion, without a real charge unless separately authorized.

One person may satisfy more than one device/accessibility condition, but each of the three blind reasoning runs must remain independent.

## Facilitator rules

- Read only the standard onboarding. Do not explain a clue, search phrase, identity distinction, or cast objection.
- Ask the player to think aloud only if they are comfortable; do not reward a particular theory with tone or follow-up.
- When blocked, let the player choose a portal hint. Do not provide an unofficial hint.
- Record timestamps and visible actions, not interpretations of the player's intelligence.
- If the build breaks, label the run technically invalid from that point; preserve useful earlier observations but do not count completion.
- Never paste private scoring keys into an agent session or networked test tool.

## Human session script

### Opening

Say:

> This is a fictional solo investigation. Use the portal and any supplied start materials as you naturally would. You may use the web-capable AI research agent provided for this test. Please open sources before relying on them. I will not answer case questions, but the portal's own hints are available. You can stop at any time.

Do not describe the generational cast or intended reveal moments before play.

### Observe without coaching

Record:

- time to identify the first actionable mission;
- first prompt sent to the agent;
- whether cited URLs are opened;
- whether the player notices source-versus-inference language;
- every accepted/invalid/duplicate evidence token;
- claim classifications and later revisions;
- search failures and which recovery tier resolves them;
- unsupported agent claims the player accepts or rejects;
- moments of surprise, skepticism, laughter, impatience, or confusion;
- whether the player can state the current question at each episode close;
- final structured choices, citations, and retry count;
- catalog disposition and rationale;
- technical errors, accessibility barriers, and support needs.

### Post-session questions

Ask in this order, without supplying names or answers:

1. What happened, in your own words?
2. Which three records did the most work in your theory?
3. What was the strongest alternative explanation, and what weakened it?
4. Which cast member did you trust first? Who changed your mind?
5. Did any cast line feel like the game declaring a fact you had not proved?
6. Where did searching feel authentic, and where did it feel like guessing the author's phrase?
7. Did you ever confuse one fictional archive with another?
8. Did the fiction disclosure give you enough context without flattening the experience?
9. What moment felt most like a reveal? What moment dragged?
10. How should the catalog handle the final identity question, and why?
11. What did you believe the product promised before starting? Did the experience deliver that?

Ask about overall satisfaction last so it does not overwrite concrete recall.

## Agent-retrieval test

Start a new agent session for each run. Do not use memory from development or earlier queries.

For every mission record:

| Field | Record |
| --- | --- |
| Agent/product/version | Exact tested system and date |
| Prompt | Verbatim player-visible prompt |
| Search query | Actual query issued when observable |
| Result opened | Exact controlled URL |
| Accession found | Yes/no and exact visible code |
| Quotation | Exact relevant field, within normal quotation limits |
| Record vs inference | Separated / blurred / failed |
| Hallucinated source or field | Exact behavior |
| Recovery used | None / citation / hint 1 / hint 2 / direct |
| Time/retries | Observed, not estimated |

Required variants:

- natural person-and-event search;
- exact distinctive phrase search;
- accession-code search after it appears in a citation;
- archive-site navigation without a search engine;
- one deliberately underspecified prompt to confirm the agent labels uncertainty;
- one prompt that suggests the leading wrong theory to test resistance;
- one source containing a historical claim that the agent must not report as established fact.

Do not label direct navigation as successful search discovery.

## Showrunner state suite

Test at minimum:

- each scene one token short;
- exact trigger completion;
- reversed discovery order;
- two scenes becoming eligible together;
- duplicate token;
- invalid token resembling a real accession;
- player ruling disagrees with expected status;
- later evidence revises an earlier claim;
- replay does not apply state effects twice;
- export immediately before and after a reveal;
- import into clean browser;
- unsupported schema/case import;
- reset with and without prior export;
- finale answer right/evidence insufficient;
- evidence sufficient/answer wrong;
- both sufficient;
- capstone direct-route attempt before success;
- network failure during sealed-envelope request and safe retry.

## Accessibility pass

Complete, rather than merely inspect:

- opening and Episode Zero choice;
- mission copy;
- archive navigation and record reading;
- document/transcript switch;
- image comparison alternative;
- token entry and error recovery;
- claim classification and revision;
- hint access;
- export/import/reset boundary;
- structured final reconstruction;
- capstone and catalog decision.

Record keyboard focus order, landmark/headings, control names, status announcements, contrast, zoom/reflow, reduced motion, transcript equivalence, and whether alt text reveals too much or too little.

## Quantitative release thresholds

These are minimums, not proof of market demand.

| Measure | Threshold |
| --- | --- |
| Understands first actionable step without facilitator coaching | 3/3 blind human players |
| Completes factual reconstruction with portal hints available | 3/3 |
| Completes without direct-link Hint 3 on more than two required records | At least 2/3 |
| Cites more than one independent evidence class for identity | 3/3 |
| Distinguishes cast claim from established record when asked | 3/3 after onboarding |
| Required sources accessible by citation/direct recovery with search absent | 100% |
| Required scene trigger tests | 100% pass |
| Protected answer/capstone early access | 0 occurrences |
| Invalid/duplicate/import cases causing false unlock or code execution | 0 occurrences |
| Required tasks completable on mobile and accessibility route | 100% |
| Critical contradiction or equally supported factual ending | 0 |
| Customer simulation reaches correct entry and completed state | 100% |

If a tester reaches the correct answer from an uncited guess, record the guess but do not count the run complete until the evidence threshold passes.

## Qualitative release questions

Owner_Bot must make an explicit judgment on:

- Did each episode change the player's model of the case?
- Did the “LOOK what we found” energy feel earned by a visible receipt?
- Did the immediate objection increase tension rather than deflate it?
- Were at least three cast personalities identifiable by method, not age label?
- Did the player retain ownership of the final theory?
- Did the ending deliver human consequence after the mechanics were solved?
- Did reality ambiguity create curiosity without causing literal real-case confusion?
- Did the use of the original 1912 product feel cumulative rather than recycled?

Any “no” requires a documented revision decision even if the quantitative thresholds pass.

## Duration and difficulty claims

Report individual observed times and conditions first. Use a customer-facing range only after at least three technically valid blind completions. State whether Episode Zero was played, which agent was used, and whether direct hints were requested.

Difficulty language must describe observed behavior—for example, number of unsupported theories, hint use, or source-comparison burden—not tester intelligence. Do not reuse duration or difficulty copy from the held legacy listing.
